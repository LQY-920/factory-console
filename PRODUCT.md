# Factory Console Product

## Register

product

## Users

Independent developers and small engineering teams operating a local-first, Issue-driven software factory. They use the console on a desktop monitor to understand pipeline health, find human decision points, and safely run a small allowlist of repeatable operations across multiple projects.

## Product Purpose

Factory Console turns the Factory Skills workflow into one dependable control surface. It reads real local Git, GitHub CLI, and per-project Factory script state, persists non-sensitive project configuration and run history, protects secrets by storing references only, and makes the next human action obvious. Success means users can switch projects without state leakage, distinguish unavailable data from real zero values, and execute guarded actions without opening an arbitrary shell.

## Brand Personality

Precise, calm, operational. The interface should feel like a well-built instrument panel: compact enough for expert work, explicit about uncertainty, and restrained in its use of color.

## Anti-references

Avoid decorative SaaS dashboards, glass effects, oversized marketing metrics, fake operational data disguised as live state, playful icon substitutes, and interfaces that hide dangerous side effects behind one-click actions.

## Design Principles

1. Real state is more valuable than optimistic state.
2. Human gates must be visible before automation can cross them.
3. Dense information should remain scannable through alignment, hierarchy, and consistent status language.
4. Every mutation explains its scope and leaves an audit trail.
5. Chinese and English are two renderings of the same product state, never separate experiences.

## Accessibility & Inclusion

Target WCAG 2.1 AA contrast, keyboard-visible focus, semantic controls, reduced-motion support, status communication that does not rely on color alone, and responsive behavior that keeps core workflows usable on narrow screens.
