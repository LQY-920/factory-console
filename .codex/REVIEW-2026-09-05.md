# Factory Console 实测与 Review — 2026-09-05

## 结论

**可构建、可启动、存在真实 API / SQLite / CLI 执行链；尚不满足原始 MVP 验收，不建议接入真实项目作为日常操作台。**

主要阻断不是视觉，而是：默认读取路径可能修改外部状态、动作白名单可绕过确认、凭证保护不完整、核心队列推导错误、项目状态串线、默认新增流程失败。

本轮依据：用户提供的《Factory-Console-Codex实现提示词.md》全文、中英文两张视觉稿、项目 AGENTS.md、源码与测试、Factory 脚本的静态调用链。此次任务是诊断，未实现产品修复。

## P1 — 投入真实使用前必须修复

### F01 默认状态读取可能产生写操作（静态调用链确认）

- 位置：server/status.ts:124–134，尤其第 130 行；../factory-skills/scripts/factory:379–398、448；其 batch_review.py:222–286。
- 总览 GET、日报预览及调度状态读取自动执行 factory next。
- 被读取的 Factory 脚本在有 origin、工作区干净且处于有效批量模式时，next 执行 `collect --apply`；后续可能编辑 PR 标签、Issue 状态。它还执行 git fetch。
- 因而“默认只读”不成立；控制台也没有为这些隐式写操作弹确认框或建立动作审计。
- 修复方向：在控制台加入已验证的只读适配层，禁止 GET / 预览 / 定时查询调用有副作用的 next。只读采集与确认后的 collect 分离；不修改用户禁止修改的 Factory 脚本。用假 CLI 调用记录证明所有读取入口不会发出写命令。

### F02 原型链键名绕过白名单和确认（R02）

- 位置：server/app.ts:85–95；server/commands.ts:21–25、46–59。
- `action in ACTION_ALLOWLIST` 接受继承属性 constructor；该属性的 mutating 为 undefined，跳过确认。buildActionCommand 未命中两个显式分支后落入 batch start。
- 隔离 API 实测：正常 batchStart + 空请求体返回 409；constructor + 空请求体返回 200，并执行假脚本的 batch start。
- 修复方向：API 和命令构造器统一使用严格枚举 / Object.hasOwn 或 Map，穷尽 switch 并拒绝 default；加入 constructor、toString、__proto__ 和所有未知动作的负例。高影响动作必须服务端确认，不能只依靠 UI。

### F03 凭证引用承诺不完整（R03、R12）

- 位置：server/schema.ts:38–41；src/components/ProjectEditor.tsx:59–62；server/status.ts:49、84–89、128–130；server/security.ts:16–25。
- Webhook URL 以 target 明文输入、持久化并经 GET 返回。使用 URL 自带密钥的 Webhook 时，这违反原始“Webhook 明文不进入浏览器和存储”要求。合成 URL 的往返探针已确认。
- 状态适配器向 runCommand 传空 secretRefs；已配置 ENV 引用的合成密钥被假脚本打印到 stderr 后，原样出现在 FactoryState.message 中。
- 修复方向：完整 Webhook URL 由服务端 ENV 引用解析；所有执行/异常/报告出口统一按项目已解析密钥脱敏，再辅以通用模式匹配。不能只做形似 token 的正则。对 API 响应、持久化日志、报告各建立泄漏断言。

### F04 新增项目默认表单保存失败（R01、浏览器复现）

- 位置：src/components/ProjectEditor.tsx:6–11、27–30；server/security.ts:3–6。
- 表单默认三个可选引用为空字符串，schema 只接受合法 ENV 名称或 undefined。用户只填显示名称和仓库路径，保存返回 400，页面显示未翻译的 invalid_project。
- 修复方向：共享输入规范化，将可选空字符串变成 undefined，或在 schema 中预处理；浏览器与真实 API 串联测试“无任何凭证也能创建”和“清空已有引用”。错误展示使用 errorKey，不显示内部错误码。

### F05 状态机不能代表要求中的批量评审流程（R04–R08）

- 位置：server/status.ts:81–104、138–177；shared/types.ts 的 GitHub 数据模型。
- 只拉取最多 100 条开放 PR / Issue，没有完整分页、当前批次过滤、已合入 integration 的子 PR、批改标签/评论、promoted 状态或 P0/P1 结果。
- 实测：普通 status:doing 被算返工；已批准但 Issue 仍 review 的条目继续算待批改；NEXT=batch-test 但没有开放 approved 子 PR 时遗漏候选测试；draft candidate PR 进入最终合入队列；已有上一版 Release 时 NEXT=tag 不再产生待发版。
- 静态另见：只要存在 latestRelease 就生成待部署，不判断已上线；Git 仓库有效就将开发阶段标记完成；GitHub unavailable 的空数组被推导为全 0 / 无待办。
- 修复方向：先建立带来源和批次关联的规范化快照，按评审/推广/候选测试/最终合入/发版/部署分离状态规则。未知必须显示 unavailable，不等同零；测试覆盖不同批次、已关闭 PR、评论决定、草稿、依赖阻塞、重复发版及已部署场景。

### F06 项目切换发生状态串线（R13）

- 位置：src/state.tsx:57–63。
- 测试顺序：A 状态请求未完成 → 切换 B → B 返回 → A 返回。最终下拉框选中 B，但 status.projectId 是 A。
- 修复方向：按项目 ID + 请求版本隔离响应，AbortController 或 generation token 拒绝过期返回；错误和 refreshing 状态同样按请求归属更新。验收应使用可控制返回顺序的测试，而不仅是瞬时 mock。

## P2 — 完整 MVP 的功能与体验缺口

### F07 编辑当前项目后永久加载（R14、浏览器复现）

- 位置：src/state.tsx:65–70、77；src/pages/ProjectsPage.tsx:16。
- 保存清除 status，但 selectedProjectId 没变，依赖它的读取 effect 不重跑。返回总览持续“正在读取真实状态”，手动刷新才恢复。
- 修复方向：保存成功显式刷新对应项目，且使服务端配置/动作相关缓存失效；不要依赖 ID 变化触发。

### F08 日报和 i18n 未闭环（R11、浏览器与源码）

- 位置：server/reports.ts:39–45；server/scheduler.ts:29–33；src/pages/ReportsPage.tsx:10–15；src/pages/PipelinePage.tsx。
- 中文预览生成后切英文，正文不更新；英文报告和流水线直接显示 Factory 的中文 summary。
- “昨日完成”是未实现说明而非真实历史；定时报告固定 zh-CN，尚无持久化的报告语言偏好。
- 通知失败时 scheduler 只存错误，不保证已生成的本地日报仍保留。调度依赖服务进程存活，未验收关闭/重启/漏触发补偿。
- 修复方向：结构化报告数据与本地化渲染分离，预览按 projectId/locale 失效，NEXT 映射双语提示；实现按项目时区的昨日历史窗口；生成成功先持久化、投递单独记结果，增加调度确定性测试。

### F09 人工任务只有汇总入口，缺少可处理明细（源码）

- 位置：server/status.ts:152–157；src/components/HumanActionQueue.tsx:16–27；src/pages/TasksPage.tsx。
- 每类仅保留第一个 URL，多条任务无法逐项查看；待发版没有 URL 导致按钮禁用；“查看命令”只打开 Release 网页，没有生成部署命令。
- 修复方向：每类汇总下展开所有关联项、来源和意见；发版/部署提供可复制命令与人工门禁，仍不自动执行合入 main、Tag、SSH。

### F10 配置验证及异常反馈不足（R09、R10、源码）

- 位置：server/schema.ts:17、46；server/reports.ts:12；src/pages/ReportsPage.tsx:14–15；src/pages/ProjectsPage.tsx:17。
- 任意非空时区通过配置校验，生成时 Intl 可能抛错；相对仓库路径也被接受，与绝对路径要求不符。
- 日报和连接检查异步失败没有完整 catch / 用户错误反馈；连接 valid 主要取决于目录和 Git，不代表 GitHub、MySQL 或部署实连成功。
- 修复方向：校验绝对路径、有效 IANA 时区，按字段返回双语错误；明确区分“配置存在”和“连接已实测”。

### F11 窄屏与键盘交互（浏览器复现）

- 位置：src/styles.css:100–106、229 起的媒体查询；src/components/Layout.tsx；src/components/ConfirmActionDialog.tsx。
- 390px 视口：页面无整体横向溢出；流水线可横向滚动，但图例自身宽 414px、容器 345px，左侧内容被裁切，中文说明挤成竖列，main 图例不可见。
- 移动端刷新按钮只剩图标且无可访问名称；导航区域名称误用“语言”；菜单文案固定 Menu。
- 确认框打开焦点仍在背景 Start Batch；Escape 不关闭，无焦点圈定与背景 inert。
- 修复方向：图例窄屏单列或允许明确可控的整体滚动；关键分支名允许完整查看；补可访问标签和规范化 dialog 焦点管理。

### F12 其他需要回归的边界（源码，未全部动态复现）

- statusCache 按 ID 缓存 10 秒，配置更新/动作完成不主动失效，立即刷新仍可能看旧状态。
- 状态读取没有将 UI 配置的 batchName 显式传给 Factory status / next，而依赖仓库当前激活批次；可能与界面分支名不一致。
- repoFromOrigin 正则拒绝仓库名称中的点，尽管项目输入 schema 允许。
- withDeadline 只结束响应等待，不取消底层工作；child.kill 只终止直接 Bash，仍需真实 Windows 进程树超时测试，避免继续产生副作用或遗留进程。

## 建议推进顺序与退出条件

1. **安全修复**：F01–F03；读取不产生外部写入、未知动作全部拒绝、合成凭证不出现在响应/日志/报告。
2. **基本可用性**：F04、F06、F07；无凭证新增、编辑后刷新、快速切换与慢响应全部通过真实 API / 前端集成测试。
3. **业务正确性**：F05、F09；建立 6 类人工任务与批次状态验收矩阵，复现实际 Factory 数据形状，所有已知错误探针转绿。
4. **完整交付**：日报历史/语言/发送失败保留、输入错误、窄屏和键盘；再做独立测试仓库的外部实连验收。
5. 完成后重新运行四项检查和新增回归测试，再由用户决定是否启用真实项目写操作。当前不建议继续堆新增功能或直接部署。
